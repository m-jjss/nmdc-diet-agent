## 作品概述

本作品面向“不同健康状况用户如何获得安全、合适、可解释的膳食推荐”这一问题，构建了一个基于 RAG 和规则约束的个性化膳食规划 Agent。系统结合 2000 道菜谱、50 份用户健康档案和自建营养数据库，在推荐前先检索候选菜谱，再依据过敏、慢性病、口味偏好和营养需求进行过滤，最后由大语言模型生成自然语言解释。

系统支持三类核心场景：单人单餐推荐、多人多约束聚餐推荐、多轮对话中的约束追加和局部替换。相比单纯让大模型直接生成菜谱，本作品把推荐范围限定在真实菜谱库内，并通过约束引擎降低“推荐不存在菜品”或“触犯健康禁忌”的风险。

## 核心能力

| 能力 | 说明 |
|------|------|
| 个性化推荐 | 根据用户年龄、性别、BMI、过敏原、慢性病、口味偏好和健康需求推荐菜品 |
| 约束校验 | 对过敏原、糖尿病、高血压、高尿酸、高血脂等条件进行硬约束过滤 |
| 混合检索 | 结合关键词检索与语义检索，兼顾精确匹配和自然语言理解 |
| 多轮交互 | 支持“不要辣”“换一道”“重新推荐”等连续对话 |
| 结果解释 | 输出推荐理由、营养信息和膳食均衡度，便于用户理解选择依据 |
| 工程部署 | 提供 Flask API、Dockerfile、Docker Compose 和部署说明 |

## 技术亮点

1. **Agent ReAct 自主推理**：通过 Function Calling 实现"思考-行动-观察"循环，LLM 自主决定调用搜索、约束检查或向用户追问，比固定流水线更灵活。
2. **RAG + 约束引擎的双层推荐机制**：先从菜谱库检索候选结果，再用健康约束过滤，减少大模型自由生成带来的不确定性。
3. **体检指标辅助识别**：系统可根据健康档案中的血压、血糖、尿酸、胆固醇等指标识别潜在饮食限制。
4. **混合检索排序**：语义检索用于理解自然语言需求，关键词检索用于保证菜名、食材、标签等精确命中。
5. **多轮对话状态管理**：记录用户已表达的偏好和约束，支持否定重推、约束追加、多人合并等 6 种交互类型。
6. **组件预热与缓存优化**：启动时加载菜谱、用户档案、营养数据库和检索索引，降低首次请求延迟。

## 数据资源

| 数据 | 规模 | 用途 |
|------|------|------|
| 菜谱知识库 | 约 2000 道菜谱 | 推荐候选、菜品详情、标签检索 |
| 用户健康档案 | 50 份 | 个性化约束、健康画像、测试样例 |
| 营养数据库 | 185 种食材 | 热量、蛋白质、脂肪、碳水、膳食纤维等估算 |
| 对话用例 | 25 组（大赛提供）+ 16 组（自测扩展场景） | 验证基础推荐、多轮交互、约束追加和方案替换 |

## 测试与验证

| 测试项 | 验证结果 |
|--------|----------|
| 基础推荐 | 可根据用户档案返回候选菜品 |
| 约束过滤 | 可过滤过敏原和常见慢性病禁忌 |
| 多轮对话 | 可记录偏好并延续上下文 |
| 对话用例 | 25 组用例通过 |
| 本地接口响应 | 检索、约束、营养计算接口可达到毫秒级响应 |

需要说明的是，本地检索和规则计算不依赖远程模型，因此响应时间较短；使用 DeepSeek v4-flash 等远程 LLM 时，端到端响应时间会受网络和模型服务影响。实际测试中首 Token 延迟约 0.9-1.25s，单轮端到端约 1.8-3.6s（流式接口），达到竞赛评优标准。

## 应用价值

本作品可作为智能厨电、家庭健康管理和数字化菜谱服务的能力模块。对用户而言，它能把复杂的健康限制转化为可执行的菜品建议；对平台而言，它能把菜谱库、用户画像和智能推荐结合起来，提升健康饮食服务的个性化程度。

## 总结

方太个性化膳食规划 Agent 以真实菜谱库为基础，以健康约束为边界，以大语言模型作为解释和交互层，形成了“检索、过滤、生成、校验”的完整推荐流程。系统已具备可演示、可部署、可扩展的工程形态，能够较好回应个性化膳食规划赛题要求。
