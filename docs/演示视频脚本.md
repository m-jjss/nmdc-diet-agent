字幕：方太个性化膳食规划 Agent｜RAG 检索｜健康约束｜多轮对话

### 0:20-0:55 问题与方案

画面展示“用户健康档案、菜谱库、约束引擎、LLM 解释”的流程图。

旁白：普通大模型可以生成菜谱，但容易出现菜品不存在、忽略过敏原、没有结合体检指标等问题。我们的系统先从真实菜谱库检索候选菜品，再根据用户健康档案进行约束过滤，最后由大语言模型生成推荐理由。

字幕：真实菜谱库 → 健康约束过滤 → 推荐解释

### 0:55-1:45 基础推荐演示

画面打开终端或 API 调试工具，依次展示健康检查、用户档案、推荐接口。

操作：

```bash
curl http://localhost:5000/api/health

curl "http://localhost:5000/api/user/profile?user_id=3"

curl -X POST http://localhost:5000/api/recommend \
  -H "Content-Type: application/json" \
  -d '{"query":"推荐一份清淡晚餐","user_id":"3","top_k":5}'
```

旁白：这里我们选择一位已有健康档案的用户。系统会读取用户的过敏信息、慢性病标签、口味偏好和体检指标，并在推荐时过滤不适合的菜品。

字幕：用户档案｜过敏过滤｜慢性病约束｜推荐理由

### 1:45-2:35 多人多约束场景

画面展示多人聚餐输入和推荐结果，重点圈出被过滤的禁忌项或推荐理由。

操作示例：

```bash
curl -X POST http://localhost:5000/api/recommend \
  -H "Content-Type: application/json" \
  -d '{"query":"三人家庭聚餐，偏清淡，避免海鲜和高糖菜品","top_k":6}'
```

旁白：在多人场景中，系统会把不同人的约束合并处理，例如有人海鲜过敏、有人需要控糖、有人偏好清淡，最终推荐尽量同时满足多方需求的菜品组合。

字幕：多人约束｜聚餐推荐｜营养均衡

### 2:35-3:30 多轮对话演示

画面展示连续调用 `/api/dialog`，突出上下文延续。

操作：

```bash
curl -X POST http://localhost:5000/api/dialog \
  -H "Content-Type: application/json" \
  -d '{"user_id":"demo_user","message":"今晚想吃清淡一点的晚餐"}'

curl -X POST http://localhost:5000/api/dialog \
  -H "Content-Type: application/json" \
  -d '{"user_id":"demo_user","message":"不要辣，也不要海鲜"}'

curl -X POST http://localhost:5000/api/dialog \
  -H "Content-Type: application/json" \
  -d '{"user_id":"demo_user","message":"换一道更适合控糖的菜"}'
```

旁白：系统会持续记录用户在对话中新增的偏好和限制。用户不需要每轮重复说明，Agent 会在后续推荐中延续这些约束。

字幕：上下文记忆｜约束追加｜局部替换

### 3:30-4:15 性能与评分

画面展示 eval.py 运行结果、Docker 启动、性能统计面板。

旁白：我们还实现了 Agent ReAct 自主推理模式，LLM 通过 Function Calling 自主决定搜索菜谱、检查约束或追问用户，替代了传统的固定流水线。工程上提供了 Flask API、Docker 部署方案和 Gunicorn 并发配置。实际测试中，首 Token 延迟约 1.3-1.4s，端到端响应约 5-7s，达到竞赛评优标准。自建评分脚本覆盖 41 组用例（16 组自建场景 + 25 组对话用例）、4 个评分维度，当前得分 97 分。

字幕：Agent ReAct｜首Token 1.4s｜eval 97分｜Docker + Gunicorn 并发

## 拍摄建议

1. API 演示时优先使用真实返回结果，不要只展示静态 PPT。
2. 推荐结果中要突出“为什么推荐”和“为什么过滤”，这比单纯展示菜名更有说服力。
3. 性能部分要区分本地检索耗时和远程 LLM 耗时，避免评审误解。
4. 录制前先运行 `python app.py`，确认 `/api/health` 返回正常。
5. 建议准备一个固定的 `demo_user`，避免临场输入造成结果不可控。
