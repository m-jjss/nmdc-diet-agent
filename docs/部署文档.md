# 方太个性化膳食规划 Agent 部署文档

## 环境要求

| 项目     | 最低要求  | 推荐配置        |
| ------ | ----- | ----------- |
| Python | 3.10+ | 3.10 或 3.11 |
| CPU    | 2 核   | 4 核及以上      |
| 内存     | 4GB   | 8GB 及以上     |
| 存储     | 10GB  | 20GB 及以上    |
| Docker | 可选    | 20.0+       |

系统默认使用 DeepSeek (`deepseek-v4-flash`)，需要配置 API Key。Embedding 默认使用 sentence-transformers 本地模型，无需外部 API。

## 本地启动

### 安装依赖

```bash
pip install -r requirements.txt
```

依赖包括 Flask、FAISS、sentence-transformers、requests 等。如果 `sentence-transformers` 安装较慢或环境不支持，系统会自动回退到确定性哈希方案。

### 配置环境变量

复制 `.env.example` 为 `.env` 并填写：

```bash
cp .env.example .env
```

编辑 `.env` 文件：

```bash
# DeepSeek 配置（必填）
DEEPSEEK_API_KEY=sk-your-api-key
DEEPSEEK_API_BASE=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-v4-flash

# Embedding 配置（可选，默认使用 sentence-transformers 中文模型 bge-small-zh-v1.5）
EMBEDDING_PROVIDER=sentence-transformers
EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
VECTOR_DIMENSION=512
```

### 启动服务

```bash
python app.py
```

启动成功后访问：

```bash
curl http://localhost:5000/api/health
```

预期返回：

```json
{
  "status": "ok",
  "service": "方太个性化膳食规划Agent",
  "version": "1.0.0"
}
```

## 并发配置

竞赛评测支持并发请求。**注意：多轮对话状态（DialogManager）依赖进程内缓存（`_dialog_managers`）加速，Gunicorn 多进程（`-w 4`）会导致不同 worker 的缓存不同步、多轮评测可能失败。** 因此评测环境必须使用「单进程 + 多线程」方案：状态共享 + 并发处理。（对话状态同时会落盘到 `.dialog_store/` 实现跨重启恢复，但内存缓存仍是同一进程内共享最可靠。）

### Linux / Docker 环境（推荐，镜像默认）

```bash
# 单进程 8 线程：多轮状态共享 + 8 路并发
gunicorn -w 1 --threads 8 -b 0.0.0.0:5000 app:app --timeout 120
```

### Docker Compose 中启用

```yaml
command: gunicorn -w 1 --threads 8 -b 0.0.0.0:5000 app:app --timeout 120
```

### Windows 环境

Gunicorn 不支持 Windows，可改用 `waitress`：

```bash
pip install waitress
waitress-serve --port=5000 --threads=8 app:app
```

### 并发说明

| 方案                                  | 并发数 | 多轮状态   | 适用                  |
| ----------------------------------- | --- | ------ | ------------------- |
| Flask 单线程（`python app.py`）          | 1   | 保留     | 开发调试                |
| Flask 多线程（`threaded=True`）          | 多线程 | 保留     | 本地/简单部署             |
| Gunicorn 单进程多线程（`-w 1 --threads 8`） | 8   | 保留     | **竞赛提交 / 评测（镜像默认）** |
| Gunicorn 多进程（`-w 4`）                | 4   | **丢失** | 不推荐（多轮评测会失败）        |

> 注意：并发数越高，需确保外部 DeepSeek API 有足够配额，避免限流。

## 竞赛 Docker 镜像提交

评测方式为**选手提交 Docker 镜像，组委会在统一环境（A100 GPU）运行评测**。

1. **构建镜像**：

   ```bash
   docker build -t fotile-agent .
   ```
2. **验证运行**：

   ```bash
   docker run -p 5000:5000 -e DEEPSEEK_API_KEY=sk-your-key fotile-agent
   curl http://localhost:5000/api/health
   ```
3. **提交镜像**：按组委会要求导出/推送镜像（如 `docker save -o fotile-agent.tar fotile-agent` 或推送至指定仓库），并在提交说明中注明 API Key 的注入方式（通过 `docker run -e` 或容器环境变量提供）。
4. **镜像内容说明**：`.dockerignore` 已排除 `.env`、`.git`、文档等非运行文件，避免密钥泄露；镜像内默认以 `gunicorn -w 1 --threads 8` 启动，多轮对话状态正常。
5. **CI 自动验证**：仓库已配置 GitHub Actions 工作流（`.github/workflows/docker-build.yml`），每次 push 自动执行 `docker build` + 容器启动 + 健康检查 + 双层对话冒烟测试（容器内 `ci_diag.py` 应用层诊断 + curl 走 gunicorn HTTP 层，覆盖评测真实请求路径），构建或接口异常会在 Actions 日志中直接体现。当前 CI 已全部验证通过（构建、启动、health、应用层与 HTTP 层接口均正常）。

## 主要配置项

| 环境变量                    | 说明                               | 默认值                           |
| ----------------------- | -------------------------------- | ----------------------------- |
| `DEEPSEEK_API_KEY`      | DeepSeek API Key                 | 空（必填）                         |

| `MAX_RETRIEVAL_RESULTS` | 单次最大检索结果数                        | `10`                          |
| `TEMPERATURE`           | LLM 生成温度                         | `0.3`                         |
| `MAX_TOKENS`            | 最大生成 Token 数                     | `2000`                        |

## 常见问题

### 依赖安装失败

`faiss-cpu` 对 Python 版本较敏感，建议使用 Python 3.10 或 3.11。如果安装失败，可先升级 pip：

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 服务启动失败

如果端口被占用，可更换端口或停止已有进程：

```bash
lsof -i :5000
kill -9 <PID>
```

### 远程 LLM 调用失败

先切换到本地模式验证基础功能：

```bash
export LLM_PROVIDER=local
python app.py
```

如果本地模式正常，再检查 API Key、网络连接和服务商模型配置。

## 安全建议

1. 不要把 API Key 写入代码仓库。
2. 生产环境应使用 HTTPS 和访问频率限制。
3. 用户健康档案属于敏感数据，正式部署前应增加脱敏和权限控制。
4. Docker 部署时建议使用独立密钥管理方式注入环境变量。
